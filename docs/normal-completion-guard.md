# HiModels 连续正常结束提醒

Stream 的 `policy.runtime.normal_completion_guard` 为请求/共享状态功能，不改变 Pool
选账号、映射模型或推理重试逻辑。生产配置仅对 free 通道启用，指定
`account_ids: ["himodels_1"]`、`scope: "himodels"`、`threshold: 2`。

- 只有真实上游的正常终止事件/JSON 结束原因才累计；代理早停标签、
  终止工具、错误、拒绝、残缺 EOF、客户端取消均不计，并打断连续计数。
- 计数仅更新于 Pool 实际选择了指定账号的请求。其他提供商不累计该计数。
- 同通道中指向同一个 Pool `upstream_model` 的公开别名和传输路由共享计数；
  不同模型和其他通道独立。
- 累计两次后，该通道/模型的下一次请求返回 HTTP 409，错误类型
  `normal_completion_guard`，中文消息明确提示再点一次重试。此次不调用推理。
  警告被原子消费、计数归零；下一次用户请求正常执行，无自动重试。
  上游自己的错误仍会如实返回，手动确认不保证上游可用。
- 精确响应缓存命中、重放历史结果不重复累计。并发请求按真实完成顺序计数，
  达阈值前已在途的请求不被中断；多个并发新请求只有一个消费警告。
- DiskCache 事务保存兼容 schema 1 的新增前缀键，跨进程/滚动更新保留，
  不用内存全局计数、不设警告过期、不清理旧状态。

验证代码、配置和旧读取器兼容后，原子更新 runtime-flags.json，再用
不可变镜像滚动发布。单文件 bind mount 使新实例读取新配置、旧实例保留
原配置；不靠非原子的就地重写或重启活跃实例启用功能。
策略放在既有 runtime 扩展对象内，旧 schema 1
读取器仍接受配置并忽略不认识的功能；共享计数键保留，回滚不清空状态。
停用仅改该策略 `enabled: false`，不变更账号状态、凭据、早停或其他配置。

验收使用离线模拟上游及真实本地 Nginx SSE/WebSocket 切换测试，
无需真实模型推理或唤醒 GPU。参见 `tests/test_normal_completion_guard.py`。
