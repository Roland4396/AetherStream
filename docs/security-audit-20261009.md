## 运行链路发现

以下行为保留在参考快照中，并已修正文档，**没有借此次公开同步改动原部署**。

### KEY-01 — 高：普通 API 的固定密钥配置未执行认证

位置：`aetherstream/api/app.py:127`；`aetherstream/api/system_routes.py:13-20`；请求入口注册与中间件。

证据：`FIXED_API_KEY` 只被读取，没有用于普通 API 的认证判断。无网络、假凭据测试中，错误的客户端凭据仍可取得模型目录响应。

影响：如果读者直接暴露服务，并误以为设置该变量已开启鉴权，非可信客户端可能调用配置好的上游。

处理：公开 README 与 `.env.example` 撤销错误的鉴权承诺；示例继续仅绑定回环地址。远程访问必须另设可靠的认证/访问控制。

### KEY-02 — 高：回放管理与日志读取接口缺少应用认证

位置：`aetherstream/api/admin_routes.py:133-152`。

证据：回放路由直接注册；隔离测试中，不带凭据和错误凭据访问回放状态均返回成功。该结论不涉及已经另行认证的 quota-keeper/lifecycle 管理接口。

影响：若这些接口可被非可信客户端访问，可能暴露诊断内容或改变回放设置。

处理：明确列为私有管理面，不可直接公开。任何外围网络保护都需要部署者独立验证。

### KEY-03 — 中：无渠道 key 时会透传客户端 Authorization

位置：`aetherstream/api/app.py:610-615`；`aetherstream/api/chat_routes.py:720-726,1585-1591`。

证据：本地 HTTP MockTransport 捕获到模型目录请求携带测试用客户端 token，没有真实上游调用。

影响：若把网关/管理凭据当作普通客户端 Authorization，可能将它发给配置的上游；模型目录发现可能访问多个渠道。

处理：按渠道配置独立的 `api_key_env`；不要复用网关管理凭据。不改变原有透传语义。

### KEY-04 — 中：完整诊断日志不是完整密钥脱敏器

位置：`aetherstream/observability/logging.py:183-205,243-249`。

证据：请求体、消息、输出和原始 SSE 为诊断目的保留；隔离测试确认放在请求体中的假 key 会进入日志。拒绝摘要脱敏只覆盖摘要字段。

影响：粘贴进对话/工具数据的 key、带凭据的 URL、或上游错误回显可能进入私有日志；分享日志时可能泄露。

处理：本次发布不包含任何真实日志、回放内容或运行状态；README/SECURITY 明确要求单独脱敏。不要把原部署的数据目录复制到公开仓库。
